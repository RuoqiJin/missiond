# Wave 16 Task 01 — Workflow Review Resolution v0

## Goal

Close the Wave15 gap: review-gate explicit resolution works for directive and plan, but workflow surface is still not wired.

Add explicit review resolution to `mission_workflow` for workflow artifacts generated by `distill` / `compile_methodology` review gates.

This is not auto-approve and not a UI feature. It is caller-push explicit resolution, matching Wave15 directive/plan behavior.

## Ownership

Expected files:

- `crates/missiond-daemon/src/handlers/knowledge/workflow.rs`
- `crates/missiond-daemon/src/handlers/knowledge/review_gate.rs`
- `crates/missiond-mcp/src/tools/knowledge/workflow.rs`

Do not modify directive or plan unless you are extracting shared pure helpers from `review_gate.rs`.

Do not modify Lisp; Wave16 Lisp backfill is a later task.

## Requirements

1. Support the same explicit resolution inputs as Wave15:

   - `review_question_id`
   - `review_decision`: `approved | rejected | needs_changes`
   - `review_actor`
   - `review_note`

2. Parse deterministic review ids:

   ```text
   review:workflow:<workflow_id>:v<version>:<action>[:<topic-hash>]
   review:methodology:<flow_id>:v<version>:<action>[:<topic-hash>]
   ```

   Follow the actual Wave14/Wave15 id derivation in `review_gate.rs`. If the existing derivation uses another scope label, use that label and document it in the report.

3. Actions:

   - For persisted workflow rows (`distill persist=true`): allow approved/rejected/needs_changes to update/return workflow review state consistently with directive/plan.
   - For methodology compiled YAML (`compile_methodology persist=true`): no DB workflow row may exist. Resolution should return a structured receipt and not fake DB state.

4. Fail fast on:

   - missing `review_decision` when `review_question_id` is present
   - unsupported scope
   - stale version
   - artifact id mismatch
   - unsupported action

5. Publish `QuestionEvent::Resolved` / `DecisionResolved` best-effort if the existing directive/plan path does so.

6. Bus publish failure must be a warning field, not a DB rollback.

## Tests

Add tests for:

- workflow deterministic id parse
- valid approved decision receipt
- rejected decision keeps artifact non-approved
- needs_changes returns next_step
- stale version fail-fast
- methodology id resolution returns receipt without DB transition
